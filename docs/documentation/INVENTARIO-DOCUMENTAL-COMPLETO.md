## Classificação definitiva

- **CANÔNICO** — fonte operacional atual; deve refletir o estado presente.
- **REFERÊNCIA** — documentação útil, mas não determina o roadmap nem o estado sozinha.
- **AUDITORIA** — evidência de uma auditoria/checkpoint; preservada para rastreabilidade.
- **ADR** — decisão arquitetural; pode continuar válida ou ser supersedida por ADR posterior.
- **MANUTENÇÃO** — registro técnico datado; não substitui a documentação canônica.
- **HISTÓRICO** — preservado por rastreabilidade, mas não operacional.
- **GOVERNANÇA** — regras para agentes/processo; deve ser reconciliada com a arquitetura atual.

## Conclusão da auditoria D0–D3

O inventário confirma que o problema principal não é ausência de documentação, mas **sobreposição temporal de documentos com diferentes estados de validade**. O conjunto de documentos de fases antigas continua útil como histórico, porém não deve ser interpretado como fila de trabalho atual.

Conflitos documentais relevantes encontrados e reconciliados:

1. Documentos das fases antigas de Auth/RBAC registram build/lint pendente, mas validações posteriores registram build/lint concluídos. O registro posterior prevalece.
2. VALIDATION_REPORT.md descreve um deployment e um modelo de autenticação anteriores, inclusive x-user-id; ele é preservado como histórico e não pode ser usado como evidência atual.
3. A documentação das demandas registra a migração de acompanhamento público para conta autenticada; portanto, documentos anteriores que descrevem protocolo como credencial devem ser tratados como históricos.
4. A Fase 29 documenta uma limitação operacional específica do bootstrap. Essa limitação não deve ser convertida automaticamente em funcionalidade ausente: implementação e validação operacional são estados distintos.
5. A Fase 31 define implementação de visibilidade documental, mas seu próprio critério de validação ainda está descrito como execução necessária; portanto, permanece dependente de validação objetiva.
6. AGENTS.md contém uma topologia de agentes e regras de escopo que não correspondem integralmente ao ciclo documental atual. Deve ser tratado como governança a reconciliar, não como fonte de estado do produto.
